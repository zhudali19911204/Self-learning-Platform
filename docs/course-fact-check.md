# 简化事实核查

在“设置与数据 → 事实核查模型”配置并保存不同于课程生成模型的模型，然后在课程页“联网搜索”下方开启“质量审查”，点击开关即保存，不触发模型调用或追溯核查旧内容。开关默认关闭，升级不自动启动付费核查；开关是全局偏好，适用于全部课程，切换模型服务不改变它。设置页不重复显示开关。生成或核查期间暂停切换；保存失败保留原状态并提示原因。路线或课程页另提供直接的“课程评分”入口，仅展示总分、维度、说明和历史，不再提供手动修订、问题处理等工具；这不影响自动核查及一轮自动修正。

## 日常流程

生成或调整一个课程模块后，程序自动请求独立模型核查事实、条件、来源引用和测验，不再要求用户进入评分或勾选修订问题。右下角显示生成、独立核查、必要修正和复核阶段。生成内容和核查记录一起保存，原有笔记、知识卡片、配图不会自动改写。

- 通常在原有生成之外增加 1 次核查。
- 问题有实际资料引文支持时，生成模型最多修正 1 次，再由独立模型复核 1 次。全部疑点消除才采用修正稿。
- 资料不足、模型答案分歧、原句无法定位、修正后仍有疑点时保留初始生成内容，标为待核实。
- 调用失败保留生成内容并显示“核查未完成”。可手动重试，不自动循环或重复计费。
- 明确标注的教学假设和虚构场景不直接判错。

阅读页每个已生成模块只显示一行“未发现明显问题／已自动修正／有 N 处待核实／核查未完成”。展开后可看原句、问题和引用依据。已自动修正的内容提供一键恢复；恢复不会再调用模型，内容之后有变化时拒绝覆盖。

同一天内，未变化的内容会复用当前模型与上下文下的核查结果。失败及含“原句待定位”项的结果不会作为重试命中，点击“核查当前版本”会重新请求模型，可能计费，但不自动重试；正文、引用资料、必要前文、核查日期、核查模型/接口或本地定位规则变化会使缓存失效。人工编辑或历史修订改变正文后，不沿用其他正文版本的状态。

## 资料与边界

### 按选择直接修正文案

核查详情中的待核实项可逐条勾选，点击“确认修正”并确认后，最多调用一次当前课程生成模型，直接更新所选疑点对应的局部文案；不要求有参考资料，不主动联网，也不会自动发起复核或反复修订。未选择范围外的文案由程序保留，不交给模型整课重写；重叠原句合并处理，重复且无法唯一定位的原句会提示重新核查。测验只更新所选疑点涉及的题目，其他题目保留，历史成绩按版本保存。

修正结果标为“已按选择修正 · 待重新核查”，不把模型修正当作事实已证实；剩余疑点继续可选，也可点击“核查当前版本”。修正前内容保留并支持恢复。已修改句段不继续沿用旧引文作为其依据，未修改句段的有效引用保留。取消不计费；调用失败、结果不合法或期间正文变化时不覆盖原文，所选疑点保留以便重试。该入口只在自动核查详情中提供，不恢复旧课程评分的修订工作台。

核查会收到当前模块的正文、当前正文保存的引用资料、课程目标和有限前文，不发送个人笔记、聊天、成绩、配图提示词或历史修订。普通核查最多提供 24 个去重资料片段；前文限最近 4 个已生成教学模块、每块最多 3000 字符。输入超限时保留原文并提示缩小模块。

只有逐字对应的原句及资料引文才能作为自动修正依据。模型摘录仅有 Markdown 加粗、强调、行内代码标记或普通文本空白差异时，程序在本地映射回正文实际存在的连续原句并保存，不改变数字、否定词、标点、运算符或代码内部空格，不做语义猜测。测验只在每个实际提供的题干、选项或解析字段内定位，不能跨字段拼接，也不能拿课程前文或资料原句替代当前目标正文。

无法定位的摘录保留模型原描述、问题理由与建议，明确显示“原句待定位”，降为 uncertain，移除依据，不把它显示成已确认错误；其他可定位疑点继续保留，不再因单条改写导致整份审查失败。有待定位项时不自动修正课程；该项没有勾选修正入口，后端也拒绝直接修正，但不影响用户明确确认后修正其他已定位项。处理其他项后，待定位描述仍保留，不能因此转为审查通过。用户可核对原文或手动重新核查，不自动追加请求。空摘录、超长摘录、缺少必要字段、无效结构或缺少测验独立答案等仍按错误处理，不以“待定位”掩盖。

修正稿重新校验正文和引用，资料 URL 与引文由程序填入；不新增联网搜索，不把模型写出的链接当成资料。旧格式、冲突的片段编号等无法安全重建依据时，不自动改写。

测验隐藏保存的答案编号让核查模型求解；模型分歧作为待核实项，不直接替换标准答案。说明文字仍提供给模型用于检查解析，因此这不是严格盲测。模型可能误判资料或同时犯错，“未发现明显问题”不是事实认证或零幻觉保证。

## 保存与兼容

当前功能面向桌面版的分块课程；旧固定结构课程仍可使用只读课程评分，不提供分块疑点修正。自动开关保存于独立的 `fact-check-settings.json`，不进入课程分享包。每模块最近 3 份、每课最多 200 份核查记录随完整学习备份保留；分享课程时排除这些记录，接收方可自行核查。

正文与状态在单个 SQLite 事务中保存，防止覆盖生成期间的新修改。自动修正前内容可恢复；涉及测验改变时使用已有题目版本与成绩隔离机制，不以新答案重算旧成绩。删除课程时同步清理核查记录和相关备份内容。

自动测试和 `node desktop/start.cjs --smoke-test --facts-only` 使用隔离数据、本地模拟模型，验证一次修正上限、引用约束、缓存、失败保留、恢复、设置开关及真实页面 → IPC → SQLite 流程，不调用真实 Key。

正文和测验使用各自的核查返回格式。真实模型偶尔省略非测验模块不适用的 `solutions: []`，程序会在本地补为空数组，不额外请求模型、不丢弃已有疑点。测验答案、问题数组和原句仍严格校验；真正的结构错误提示具体字段，保留正文，不能把格式失败当作核查通过。

核查模型应使用 `sources.id` 的 R 编号。模型若使用资料中实际存在的片段编号（如 `[S1E1]`），只有编号能唯一对应且引文逐字存在时，才在本地转为对应 R 编号。资料编号不存在、引文被改写、虚构或无法唯一对应时，移除该疑点的全部引文依据，降为“待核实”并显示“引用待核实”说明；其他疑点继续保留。此类引用不再导致整份核查失败，也不会被用于自动修正，用户仍可勾选并明确确认修正文案。此过程不联网、不追加模型请求，也不将无法核实的引用伪装成真实依据。

`test-support/fact-check-live.cjs` 是显式授权的付费诊断入口：必须指定 `--confirm-paid`、`--lesson=...` 和 `--block=...`，每次最多一次真实核查，只读课程和配置、不保存核查结果、不请求修正、不自动重试。正文、有限前文与已有引用会发送至已配置的核查模型，运行前需确认对应数据和服务目的地的授权；密钥不输出。
