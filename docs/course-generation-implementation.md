# 课程首次生成优化：实施与验证记录

日期：2026-10-12。提示词版本：`course-generation-v2`。

## 已接入

- 路线按可验证成果、必要先修和时间取舍规划，不强行将理解类目标做成项目课。大纲按模块目标配对讲解与案例，接收本课 `minutes`；该时长是整课预算，不是每块预算。
- 第7节的共同与五类教学规则已接入 `course-generation.mjs`。格式规则集中在输出部分；JSON外不能有围栏或额外说明，正文字符串中可保留Markdown和程序代码围栏。反馈重生成与可选配图规则继续保留。
- `public/teaching-context.js` 为生成和“换个讲法/例子/任务”构造教学正文上下文。案例优先提供相邻对应讲解的完整正文；测验、总结读取前序已生成的讲解、案例、实践，不再只有最近三块开头。
- 没有前序教学正文时，测验和总结在页面与服务端停止生成，不调用模型。已有部分内容时可以按需生成，页面提示范围；不会自动生成其他模块，不增设付费调用或重试。

## 上下文边界

每次最多24个正文来源、80个模块目录条目、36000个正文字符。普通单课材料能装下时传完整正文；长课优先目标相关材料并照顾首尾模块。配套讲解优先完整保留，其他来源公平分配剩余空间。

长正文保留开头、按目标关键词选取的段落附近与结尾，带模块ID、类型、目标、顺序和字符位置 `start/end`。这是本地规则选取的原文片段，不是经过模型总结的知识点，更不是语义检索保证；字符位置采用JavaScript字符串的UTF-16索引。多个片段之间有省略，提示词明确禁止把它们当成连续原文或完整程序。

`coverage` 标明前序教学模块中未生成、未提供、节选的范围。`completeBefore`只表示前序讲解/案例/实践正文被提供，不代表学生学过，也不代表整课已完成或知识已核验。课程图像URL、历史修订、笔记、聊天、成绩和API Key不进入新增教学上下文。

调用次数没有因本次优化增加，但更完整的正文会增加单次输入token，可能提高费用和延迟。36000字符是应用的上下文上限，不是模型token数或费用保证；使用小上下文模型时仍需按实际服务限制验收。

## 生成校验与历史兼容

新生成大纲检查讲解紧接案例、测验排在讲解后、标题与目标不重复。新生成测验要求2–4道不同题目、每题四个不同选项；保留原结构、答案和解析范围校验。模型返回不合格正文或大纲时只报错，不暗中追加修正调用。

历史课程、JSON导入、SQLite读取及第二期局部修订继续使用原契约，仍接受历史的1–5题和未配对旧大纲；不会因为新规则而强行迁移旧教材。结构检查不证明目标真的覆盖、事实正确或答案唯一，独立评审和修订闭环继续保留。

## 对比验证准备

`test-support/generation-cases.mjs` 已准备10个手写需求和验收点，覆盖零基础/有基础/进阶，技术、语言、理论理解与宽泛目标。它们不是人工审核课程样本，也没有标准课程全文。

真实对比尚未执行。建议先选Git身份配置、SQL周报、认知偏差三个需求，在用户确认调用上限后进行：

1. **提示词单独对比**：冻结同一份输入与正文来源，固定生成模型、参数及额度，只改变提示词；原规则参考优化前文档快照。不要同时改变上下文再归因于提示词。
2. **流程对比**：分别按旧/新上下文和大纲流程生成，检查整课连贯性，明确结果来自组合变更。
3. **盲审**：向独立评审隐藏新旧版本名，固定同一模型和标准；人工重点核对严重问题与模型分歧，不把评审评分当准确率。
4. 记录首次结构成功、目标覆盖、讲解与案例一致、测验是否越界、实践材料是否完整，以及耗时、调用次数和实际费用/供应商用量。
5. 小样本只能作为冒烟验收，不宣称统计显著改善。首次失败需计入，不能只展示重新生成成功的样本。

## 本轮验证

新增自动化检查涵盖配套讲解结尾、前半课覆盖、乱序与未生成内容、长文片段位置和总预算、输入脱敏、新旧契约兼容及失败无自动重试。运行全库回归与独立Electron集成测试；测试使用合成材料和模拟模型，不作为教学质量实测数据。

首次生成优化阶段未增加单块时间预算、知识点结构映射、联网事实核验、付费自动评审或自动修订。旧安装包不会自动更新，需要启动源码测试版或重新打包。

2026-10-15 后续已接入可独立开启的[课程正文联网资料辅助生成](course-source-assisted-generation.md)：搜索优先原始文档，排除论坛、问答、自媒体等来源后读取网页，生成具体模块，并从正文引用标记自动提取句段，在课末汇总参考文档。新网站无需逐个登记。该功能提供来源追溯，不等于逐条事实核验或零幻觉保证。
